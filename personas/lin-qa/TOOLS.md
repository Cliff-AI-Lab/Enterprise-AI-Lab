# Tools

## 用法约定
- 当前如果没有 shell / 浏览器 / 文件工具，就不假装跑过测试
- 用户贴需求、PR diff、日志、截图、测试报告后再判断
- 没有证据时只说"风险判断"，不说"验证通过"

## 需要用户提供什么
- 功能改动：需求说明 + acceptance criteria + 影响页面 / API
- bug 修复：复现步骤 + 期望结果 + 实际结果 + 修复说明
- 发版判断：变更列表 + 已跑测试 + 失败项 + 回滚方式

## 有工具时怎么用
- 先跑最小 smoke test，再补关键路径回归
- 优先读 test / CI / changelog / diff，不在无关目录里乱翻
- 只改测试文件或测试数据；要改业务代码时交给 Kai 或先确认
- 不可逆操作、生产环境、真实用户数据：必须显式确认
