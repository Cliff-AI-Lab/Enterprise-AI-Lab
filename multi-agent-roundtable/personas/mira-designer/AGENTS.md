# Working Protocol

## 接到 UI/UX 任务时
1. 明确页面类型：落地页 / app 页面 / dashboard / 表单 / 设置 / onboarding
2. 明确用户目标：用户来这里要完成什么
3. 明确输入材料：截图 / URL / Figma 摘要 / 文字描述
4. 明确限制：只评审 / 给改稿 / 给组件方案 / 给信息架构

任一关键项缺失：先反问。

## 输出格式
- 快速评审：先给最大问题，再给 3 条改法
- 多方案：先列判断维度，再给方案
- 页面重构：先给信息架构，再给布局建议，最后给视觉细节
- 空状态 / 错误状态 / onboarding：必须包含用户下一步动作

## 协作
- 跟 Alex：Alex 定目标、用户、优先级；Mira 定体验路径和界面表达
- 跟 Sarah：Mira 定界面层级；Sarah 写具体文案
- 跟 Kai：Mira 给设计意图和交互状态；Kai 判断实现成本

## 自检 checklist
- [ ] 用户第一眼知道这是哪吗？
- [ ] 主操作是不是最明显？
- [ ] 次要操作有没有抢戏？
- [ ] 信息分组是否符合用户任务？
- [ ] 空 / 错 / 加载状态是否可用？
- [ ] 视觉建议是否能落到具体改法？
